# След — навигатор финансового расследования

Локальный анализ транзакционной сети: роли участников, кластеры, очередь приоритетов, объяснения и следующий запрос. Свободный диалог работает с OpenAI API или локальной Ollama; вычисления выполняются инструментами Python.

Это папка готового проекта `finalWork`. В репозиторий включены исходники, тесты, документация и генератор синтетических данных. Реальные входные файлы, рассчитанные отчёты, журнал решений, `.env`, API-ключи и виртуальное окружение поставляются отдельно и сюда не входят. Упоминания результатов на предоставленном наборе в документации описывают локальную проверку автора; соответствующие файлы не опубликованы.

## Быстрый запуск на синтетическом примере

Команды выполняются из папки `finalWork`. Нужен Python 3.10–3.13. Синтетический CSV-пример, расчёт графа и локальный интерфейс не требуют сторонних библиотек или API-ключа:

```shell
python -m moneygraph demo --out results/demo --size 2248 --stability
python -m moneygraph serve --data results/demo/input --out results/demo --format csv --port 8520
```

Откройте http://127.0.0.1:8520. Без подключённой модели доступны очередь, факты, граф и журнал; чат покажет, что модель не настроена. Автономный отчёт можно открыть отдельно: `results/demo/dashboard.html`. Демо создаёт явно синтетические данные, которые не доказывают качество ролей на реальных операциях.

Для ответов OpenAI скопируйте `.env.example` в `.env` и укажите собственный `OPENAI_API_KEY`; альтернативный локальный провайдер — Ollama. Настройка и требования к сети описаны в `docs/AI_SETUP.md`. Ключ нужен только серверу и не должен попадать в Git. При использовании OpenAI отправляются вопрос, история и выбранные инструментами факты. Баллы роли — сила правил, не вероятность виновности; выводы проверяет аналитик.

`START.cmd` и `scripts/start_local.ps1` предназначены для отдельно предоставленных реальных файлов в `data/` и подготовленного `.venv`. Для опубликованного синтетического примера используйте команды выше.

## Запуск на данных хакатона

Один раз установите зависимость чтения Parquet, желательно до хакатона:

```shell
python -m pip install -r requirements.txt
```

Поместите `nodes.parquet`, `edges.parquet`, `transactions.parquet` в `data/`. Затем одна команда создаёт все результаты:

```shell
python -m moneygraph run --data data --out results/real --format parquet --stability
```

Для ручной настройки порогов:

```shell
python -m moneygraph run --data data --out results/real --config configs/default.json
```

Рекомендуемая среда для зафиксированного Parquet-пакета: Python 3.10–3.13. Входной контракт описан в `data/README.md`. CSV поддерживаются для автономного развития и тестов.

## Результаты

| Файл | Содержание |
|---|---|
| `nodes_roles.csv` | Все узлы: gid, role, role_score, cluster_id, priority_score, evidence |
| `clusters.csv` | Размеры, seed, внутренний оборот, основные gid, гипотеза |
| `top_nodes.csv` | Не менее 20 узлов при наличии такого числа во входе; сортировка по приоритету |
| `dashboard.html` | Поиск gid, направленный граф, фильтры, карточки, топ, кластеры и запросы; без сервера/CDN |
| `features.csv` | Все рассчитанные признаки |
| `next_queries.csv` | Отдельная очередь запросов с учётом нового охвата |
| `stability.csv` | При `--stability`: чувствительность роли к трём наборам порогов |
| `report.json` | Полная модель для интерфейса и дальнейшей разработки |
| `validation.json` | Сверка таблиц, ограничения и контроль выходной схемы |
| `run_manifest.json` | Конфигурация, версии, SHA-256 входов/выходов и время выполнения |

CSV имеют UTF-8 BOM для удобного открытия в Excel. В JSON идентификаторы передаются строками, чтобы браузер не округлил int64. В карточке показано до 100 исходных транзакций на узел; полный список остаётся во входных файлах.

## Проверки

```shell
python -m unittest discover -s tests -v
```

Проверка Parquet выполняется при установленном `pyarrow`; иначе явно пропускается. Смотрите `docs/VALIDATION.md` и воспроизведите проверки локально; логи предыдущих запусков не включены в репозиторий.

При установленном Node.js дополнительно проверьте логику автономного интерфейса:

```shell
node tests/test_dashboard.cjs
```

Эта команда проверяет JavaScript и взаимодействия с моделью DOM; реальную отрисовку браузера нужно проверить отдельно. Node.js нужен только для этой дополнительной проверки.

## Эксперимент со следующим запросом

```shell
python -m moneygraph benchmark --data results/demo/input --format csv --out results/benchmark --budget 10 --random-runs 3
```

Он имитирует обрыв на втором и третьем колене, затем раскрывает исходящие выбранного узла. Сравнивает фиксированную эвристику с входящим объёмом, числом плательщиков и случайным выбором. Эталон — полный предоставленный файл, не истинные преступные роли. Победа эвристики не гарантируется и не зашита в эксперимент.

## Навигация для кодера

- `docs/CODER_HANDOFF.md` — что менять после получения данных, ограничения и порядок работы.
- `docs/METHODS.md` — точные правила ролей, скоринг, кластеризация, время и свидетельства неоднозначности.
- `docs/REVIEW.md` — независимая проверка требований и опасных ошибок.
- `docs/SPEC_MAP.md` — соответствие требованиям исходного PDF.
- `docs/IDEAS_REVIEW.md` — какие идеи из обсуждения объединены и какие исключены.
- `docs/PITCH.md` — пятиминутная защита на реальных результатах.
- `docs/ROADMAP.md` — план пяти часов и масштабирование до миллиона узлов.
- `docs/PRODUCT.md` — коммерческая гипотеза, пилот и измерение ценности.
- `docs/architecture.mmd` — схема решения для одного слайда.

Текущие результаты проверок предоставленных файлов описаны в `docs/RUN_REAL_AI.md` и `docs/VALIDATION.md`. Интеграция моделей тестируется имитацией HTTP-ответов отдельно от реальных вычислений; такой тест не подтверждает доступность API или качество ответов живой модели.
