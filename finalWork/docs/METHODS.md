# Методы и точные правила

## 1. Наблюдение и интерпретация

Граф — направленные агрегированные переводы за предоставленный период. Узлы добавляются из nodes, включая изоляты. Суммы и число transactions сверяются с edges. Структурная достижимость и временная совместимость не доказывают происхождение одних и тех же денег. Баланс `in_kzt - out_kzt` называется только наблюдаемым сальдо, не остатком счёта или доходом.

`role_score` — нормированная сила правила; `priority_score` — операционный приоритет проверки; `role_retention` — доля совпадений на трёх вариантах порогов. Ни один из них не является вероятностью виновности.

## 2. Признаки

- `in_degree`, `out_degree`: уникальные контрагенты, исключая сам узел.
- `in_kzt`, `out_kzt`: суммы всех наблюдаемых входящих/исходящих, включая self-transfer. Общий оборот датасета считает каждый перевод один раз.
- `seed_reach`: число разных seed с направленным путём не длиннее четырёх рёбер; сам seed не считается своим источником. Циклы подавляются visited-set.
- `paths`: до трёх структурных путей-свидетельств; хронология по ним не подтверждена.
- `predecessor_groups`: число кластеров входящих соседей. Это не число независимых путей.
- `external_clusters`: число соседних кластеров, отличных от собственного.
- `centrality`: directed unweighted Brandes по воспроизводимой выборке максимум 64 активных источников. Это приближение; денежные суммы не используются как расстояния.
- `out_entropy`: нормированная энтропия сумм исходящих по разным получателям; 0 для менее двух получателей.
- Перцентили: доля положительных значений признака, не превышающих текущее. Нулевой признак получает 0; совпадающие значения получают одинаковый перцентиль.
- `seed_norm = seed_reach / max(seed_reach)` по текущему графу; если максимум 0, используется знаменатель 1.

## 3. Время

Для узла входящие и исходящие группируются как пары (день, сумма). FIFO-сопоставление тратит входящую сумму не более одного раза внутри расчёта и ищет последующие исходящие в пределах 1–2 дней. Полученная сумма делится на наблюдаемый вход (`temporal_ratio`). Self-transfer в сопоставлении не участвует. Два дня — значение `temporal_days` по умолчанию; при настройке применяется указанное число.

Второй расчёт допускает тот же день (0–2 дня). Его превышение над строгим расчётом сохраняется как `same_day_extra_kzt`: порядок событий внутри дня неизвестен. Два расчёта — альтернативные оценки; их суммы не складываются. Это совместимость по времени и сумме, не отслеживание конкретных денежных единиц. Начальные остатки и внешние поступления неизвестны.

`right_censored` означает наличие поступления у конца наблюдаемого диапазона дат: дата не раньше последней наблюдаемой даты минус `temporal_days`. Диапазон определяется фактическими транзакциями, поэтому это консервативный индикатор, а не доказательство полноты календарного месяца.

`max_depth` ограничивает только поиск путей от seed. Физическая граница исходной выгрузки фиксирована протоколом кейса: `depth >= 4`. Увеличение глубины поиска не открывает отсутствующие данные. В контролируемом эксперименте граница задаётся отдельно списком ещё не раскрытых узлов.

## 4. Кластеры

Направленные рёбра превращаются в неориентированные для кластеризации, складывая вклады двух направлений. Вес каждого направленного вклада: `log(1 + sum_kzt)`. Self-loop не влияет на разбиение.

Одноуровневая локальная оптимизация модульности: начальная метка отдельная на каждый узел, до 15 воспроизводимых перестановок обхода, resolution=1. Для переноса узла в сообщество используется `k_in - resolution * k_node * total_community / total_degree` после временного удаления его из старого сообщества. Перенос выполняется только при улучшении. Это локальный эвристический поиск, не полноценный многоуровневый Louvain и не гарантия глобального оптимума.

Несвязные остатки сообществ разделяются; изоляты получают отдельные кластеры. Нумерация стабилизируется по минимальному gid. Внутренний оборот кластера считает каждое исходное направленное ребро ровно один раз, включая self-loop.

## 5. Роли

Обозначения: `S=seed_norm`, `I/O` — перцентили входящей/исходящей суммы, `B` — перцентиль центральности, `T=temporal_ratio`, `E=out_entropy`, `N=n_tx`. Все итоги ограничены диапазоном [0,1]. В формулах min(x,1) означает насыщение признака.

| Роль | Допуск | Сила правила |
|---|---|---|
| consolidator | in_degree ≥ 3 | .45 + .25·min(in_degree/8,1) + .15·S + .15·I |
| distributor | out_degree ≥ 5 | .45 + .30·min(out_degree/20,1) + .15·E + .10·O |
| transit | Не seed, не граница; вход>0; .8≤out/in≤1.2; T≥.5 | .45 + .30·T + .15·balance + .10·min(N/5,1) |
| terminal | Не seed, не граница; вход>0; out/in≤.1 | .35 + .25·min(in_degree/5,1) + .20·(нет right_censored) + .10·min(N/4,1) |
| coordinator | seed_reach≥3; external_clusters≥2; centrality>0; B≥.9 | .45 + .25·S + .20·B + .10·min(external_clusters/3,1) |
| peripheral | Ни одно правило выше не прошло | .1 при отсутствии переводов, иначе .2 |

`balance = 1 - min(abs(out/in - 1) / max(1-transit_min, transit_max-1, .01), 1)`.

При нескольких допусках побеждает максимальная сила; при равенстве — лексикографический порядок имени роли. Остальные роли сохраняются в `alternatives` карточки JSON. Классы не назначаются принудительно ради наличия всех шести.

Граница depth≥4 блокирует только интерпретацию отсутствующих исходящих как terminal/transit. Наблюдаемые признаки консолидации у пограничного узла сохраняются. В контролируемом эксперименте граница задаётся фактом отсутствия раскрытия конкретного узла, даже если его текущий depth меньше четырёх.

`terminal` всегда кандидат в наблюдаемом срезе. `coordinator` — структурная гипотеза; руководство группой из центральности не следует.

## 6. Приоритет

`priority = .35·S + .20·V + .20·B + .15·R + .10·D`, где V — перцентиль in+out, R — сила основной роли, D — перцентиль числа входящих контрагентов. Для узла без переводов приоритет равен 0.

Веса можно переопределить списком из пяти значений; результат делится на их сумму. Неполнота данных не обнуляет важный пограничный узел. `top_nodes.csv` сортируется строго по убыванию приоритета, затем по числовому gid.

## 7. Следующие запросы

Это отдельная очередь. На каждом шаге выбирается максимум:

`priority * (.6 + .2 * доля новых seed + .2 * новый кластер) * (1 + .15 * признак неопределённости)`.

Признак неопределённости: boundary, seed или right_censored. Покрытие seed/кластеров обновляется после выбора. Это прозрачная эвристика разнообразия, не доказанно оптимальная стратегия и не оценка математического ожидания информации.

Шаблон запроса зависит от причины неопределённости: исходящие за тот же период без обрыва обхода; полные входящие; продолжение временного окна; уточнение времени и полноты.

## 8. Свидетельство неоднозначности

Для пограничного узла без исходящих строится второй топологический сценарий с одним гипотетическим продолжением. Исходящий BFS от всех seed до четырёх рёбер повторяется для обоих сценариев. Свидетельство включается, только если исходный обход воспроизводит все наблюдаемые рёбра, обе выгрузки совпадают и исходящая степень рассматриваемого узла меняется.

Это вычислительная проверка неидентифицируемости терминальности относительно указанного способа наблюдения. Гипотетический перевод не добавляется во входные таблицы, роли, обороты или обязательные CSV. Он не содержит утверждения о реальном неизвестном получателе. В отчёт включается максимум 30 примеров.

## 9. Чувствительность

`--stability` меняет минимальный fan-in, fan-out, число seed для coordinator и порог временной совместимости на коэффициенты .8, 1, 1.2. Метрики и кластеры фиксированы. Вывод — совпадение основной роли с базовой в 0/3…3/3 сценариев. Это ограниченный анализ порогов, не бутстрэп, не доверительный интервал и не полная устойчивость к пропускам.

## 10. Эксперимент раскрытия

Файл глубины 4 служит ограниченным эталоном. Начальные состояния раскрывают исходящие только отправителей глубины<2 или<3. Индуцированный подграф не используется: исходящие пограничного узла обратно в известный граф тоже скрываются.

Алгоритм выбирает только видимые ещё не раскрытые узлы с текущим расстоянием<4. Выбор не использует скрытую степень, сумму, полную кластеризацию или истинные роли. Нулевой результат запроса тоже тратит бюджет. Настоящие неизвестные исходящие четвёртого колена не подменяются нулями.

Сравниваются эвристика приоритета с дополнительным seed-охватом, видимый входящий объём, видимое число плательщиков и случайный выбор. На каждом шаге признаки пересчитываются по текущему графу. Для ускорения во всех частичных расчётах и эталоне используются 16 источников центральности и 8 итераций кластеризации.

Метрики: совпадение с top-20 полного файла, ошибка восстановления входящих сумм его top-20, число раскрытых транзакций, запросы до 90% совпадения и нормированная площадь кривой. Они не измеряют точность поиска преступников. Критерии фиксированы; превосходство своей эвристики не гарантируется.
