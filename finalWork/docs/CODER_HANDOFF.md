# Передача кодеру

## Что готово

- CLI, чтение трёх таблиц Parquet/CSV, проверка схемы и сверка агрегатов.
- Предоставленные файлы уже в data/; их полный расчёт сохранён в results/real/.
- Расчёт предполагаемых ролей, приоритета, сообществ, seed-путей и временной совместимости.
- Три обязательных CSV точной схемы и дополнительные признаки/следующие запросы.
- Автономный HTML-отчёт с включёнными данными, без CDN.
- Локальный интерфейс помощника и HTTP-сервер на 127.0.0.1.
- Адаптеры OpenAI и локального Ollama с вызовами локальных графовых инструментов; отсутствие провайдера явно показывается как ошибка настройки.
- Пороговая чувствительность, сценарии неоднозначности и синтетический эксперимент следующего запроса.
- Проверки ядра, инструментов и серверной интеграции. Исходные Parquet прочитаны, записаны и повторно прочитаны с точным совпадением.

## Текущий фактический результат

Предоставленный набор: 2 248 клиентов, 3 119 рёбер, 4 840 транзакций и 81 seed за июль 2026 года. Исходные gid сохранены без float-преобразования, все узлы включены в результат. results/demo/ остаётся отдельным инженерным примером и не должен подменять результат кейса.

В .venv установлены Python 3.12.14 и pyarrow 21.0.0. Расчётный анализ работает локально без API-ключа. 23 сентября 2026 года в браузере получен живой ответ OpenAI gpt-4.1-mini с четырьмя вызовами инструментов по предоставленной выгрузке. Серверу необходим сетевой доступ; запуск в ограниченной среде ранее приводил к отказу соединения. Локальная Ollama недоступна и с живой моделью не проверена. Автоматические тесты адаптеров используют подменённый HTTP-транспорт и проверяются отдельно от живого запроса.

## Следующая последовательность действий

1. Прочитать results/real/validation.json, warnings и run_manifest.json. Не подавлять ошибки сверки сумм или числа переводов.
2. Запустить python -m unittest discover -s tests -v и python scripts/validate_real_parquet.py из окружения проекта; Parquet-проверка теперь должна выполняться без пропуска.
3. Выбрать провайдера по .env.example. Для локальной модели нужен работающий Ollama с моделью, поддерживающей инструменты. Для OpenAI нужен собственный ключ и разрешение на передачу соответствующего контекста данных внешнему сервису. Ключ хранится в локальном .env, не в HTML или переписке.
4. Запустить python -m moneygraph serve --data data --out results/real --port 8520 или scripts/start_local.ps1.
5. Открыть http://127.0.0.1:8520 и проверить фактический статус провайдера. Присутствие ключа в файле не доказывает успешный ответ модели.
6. Проверить запрос «Кого проверить первым?», затем карточку узла и вопрос об основаниях. Сопоставить возвращённые факты с операциями. Инструментальные вызовы показывают проверяемые действия, а не скрытые рассуждения модели.
7. Проверить поиск трёх произвольных gid: seed, пограничный узел и изолят. Все роли и связи формулировать как гипотезы.
8. При необходимости повторить benchmark на предоставленном наборе в отдельную папку. Показать фактические результаты, даже если простой baseline лучше. Существующий benchmark относится к синтетическому примеру.

При замене данных сохранить тот же контракт таблиц, повторить запуск и сверку. Расхождения с PDF выяснять по входам, не исправлять алгоритм до заранее ожидаемых чисел.

## Где менять код

| Задача | Файл |
|---|---|
| Поля, типы, Parquet, сверка таблиц | moneygraph/data.py |
| Признаки, роли, приоритет, кластеры | moneygraph/engine.py |
| CSV/JSON/HTML и manifest | moneygraph/pipeline.py |
| Локальные инструменты для модели | moneygraph/assistant_tools.py |
| Адаптеры модели и ограниченный цикл инструментов | moneygraph/assistant.py |
| HTTP/API и разрешённые локальные файлы | moneygraph/server.py |
| Интерфейс помощника | moneygraph/assistant.html |
| Автономный графовый отчёт | moneygraph/dashboard.html |
| Команды | moneygraph/__main__.py |
| Эксперимент раскрытия | moneygraph/experiments.py |
| Синтетические инженерные данные | moneygraph/synthetic.py |
| Проверки ядра | tests/test_moneygraph.py |
| Проверки инструментов и серверной интеграции | tests/test_assistant_tools.py, tests/test_assistant.py |
| Проверка записи исходных Parquet | scripts/validate_real_parquet.py |

Не меняйте DOM-контракт JSON без одновременного изменения шаблона. gid в JSON всегда строки. Встраиваемый JSON экранирует символ <, чтобы поле не могло закрыть script. Числовые факты должны поступать из расчётных инструментов; ответы модели не подменяют выгрузки и проверки.

## Границы MVP

Это локальный анализ одной выгрузки с интерактивным помощником. Учётных записей сотрудников, многопользовательских разрешений, регуляторной отправки, автоматической блокировки счетов и потокового подключения банка нет. Пользователь решает, подключать ли внешний API: при OpenAI в сервис передаются вопрос, история разговора и выбранные инструментами факты; Ollama обращается к локальному серверу.

Кластеризация эвристическая; путь по графу не доказывает движение тех же денег. Пороговые правила не обучены на размеченных ролях, которых в кейсе нет. Граница четвёртого колена не позволяет восстановить невидимые переводы как факты. Перед пилотом измерить качество выводов, время проверки человеком и стоимость настоящих вызовов модели.
