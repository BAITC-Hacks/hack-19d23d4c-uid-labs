# Подключение настоящего ИИ

Расчёты графа и очередь работают без модели. Свободный ответ появляется только после настоящего вызова модели. Код не подменяет его готовым текстом, если ключ отсутствует или запрос завершился ошибкой.

## OpenAI API

1. В корне проекта скопируйте `.env.example` в `.env`.
2. Откройте `.env` локально в VS Code и заполните `OPENAI_API_KEY`. Не присылайте ключ в чат.
3. Оставьте `MONEYGRAPH_PROVIDER=openai`. Модель по умолчанию — `gpt-4.1-mini`; можно указать другую модель с Responses API и function calling, доступную вашему аккаунту.
4. Запустите `START.cmd` и откройте http://127.0.0.1:8520. Если сервер уже работает, обновите статус после сохранения файла.

```dotenv
MONEYGRAPH_PROVIDER=openai
OPENAI_API_KEY=ваш_ключ_только_в_локальном_файле
OPENAI_MODEL=gpt-4.1-mini
```

При вопросе API получает текст вопроса, последние сообщения и факты, выбранные инструментами: gid, суммы, даты, связи, гипотезы. Полный архив не загружается. Используйте этот режим, когда отправка этих сведений OpenAI разрешена вашей командой. Запросы API оплачиваются по аккаунту провайдера. `store=false` отключает сохранение Responses для дальнейшего обращения через API; это не обещание отсутствия любых журналов у провайдера.

Ключ находится только на сервере и исключён из Git/выдаваемого архива. Наличие ключа означает «настроено», а доступность проверяется фактическим запросом. При ошибке авторизации, лимита или сети показывается ошибка, а не выдуманное расследование.

Если отдельная проверка ключа проходит, а чат сообщает об отказе в сетевом доступе, проверьте способ запуска сервера. Процесс в ограниченной среде может не иметь доступа к OpenAI. Остановите его и запустите `START.cmd` из папки проекта либо разрешите сетевой доступ для запуска приложения в Codex. Менять рабочий ключ или устанавливать Ollama для режима OpenAI не нужно. Кнопка «Обновить настройки» перечитывает конфигурацию; она не отправляет проверочный запрос модели.

Официальная схема интеграции: [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling), [модель GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini).

## Локальная модель Ollama

Установите Ollama с официального сайта и загрузите модель, поддерживающую tools, например `qwen3:8b`:

```shell
ollama pull qwen3:8b
```

В `.env`:

```dotenv
MONEYGRAPH_PROVIDER=ollama
OLLAMA_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3:8b
```

Ollama должна работать. Если сервис не запущен, используйте `ollama serve`. Размер модели и скорость зависят от компьютера; скачивание весов требует интернета, обработка после скачивания локальная. Этот вариант не проверялся с живой моделью на данном компьютере: Ollama здесь не установлена. Код проверен тестовыми HTTP-ответами согласно [официальной схеме tool calling](https://docs.ollama.com/capabilities/tool-calling).

## Как использовать для работы

1. Просмотрите первые строки очереди. Красный означает высокий приоритет проверки, а не установленное преступление.
2. Выберите gid и спросите: «Почему этот участник выше остальных? Покажи основания и что проверить дальше».
3. Уточняйте произвольно: «Найди общих получателей у этих двух участников», «Какие пары переводили чаще всего?», «Покажи исходящие переводы за 10–15 июля больше 100 000 тенге».
4. Раскройте выполненные проверки: каждая содержит аргументы инструмента и полученные данные. `tx:N` — номер строки `transactions.parquet`, а не банковский номер операции. Источник не меняется при сортировке.
5. Откройте полный граф и проверьте основания. В карточке участника на странице ИИ сохраните решение: «Передать на проверку», «Запросить сведения» или «Сейчас не продолжать», при необходимости с комментарием. Запись добавляется в локальный `results/real/reviews.jsonl`, сохраняется после перезапуска и привязана к хешам исходных файлов. Новое решение не стирает историю. Запрос банку не отправляется, банковская операция не выполняется. Это журнал одного локального рабочего места без корпоративной авторизации; модель не может записывать решения.

Чат хранит текущую историю в памяти вкладки; после перезагрузки она сбрасывается. В новый запрос передаются последние сообщения; числовые факты модель должна заново получать инструментами. Лимит: шесть шагов исследования и дополнительный шаг итогового ответа, до двенадцати вызовов инструментов. Сложные вопросы можно разделить. В интерфейсе перечислены выполненные проверки, а не скрытые рассуждения модели.

## Проверки и ограничения MVP

Все суммы, фильтрация, частоты, пути и группировки рассчитываются Python по исходным таблицам. Модель выбирает последовательность инструментов и объясняет результат. Семь инструментов доступны только для чтения; произвольный Python/SQL не исполняется. Ответ без успешной проверки инструментом не выдаётся как результат. Это снижает риск выдумок, но не гарантирует правильность каждого вывода модели: ссылки и расчёты доступны для проверки человеком.

Нет разметки преступных ролей, поэтому нельзя объявить accuracy или процент виновности. Нет замеров работы аналитиков, поэтому экономия до десяти минут пока является проверяемой целью пилота. Редкость/частота — описание пар переводов внутри периода, а не самостоятельное основание обвинения.

Сервер доступен только на текущем компьютере. Для внедрения в банк потребуются корпоративная авторизация, журнал доступа и решений, согласованный контур данных и отдельная оценка качества. В текущем MVP нет автоплатежей, блокировок счетов или отправки регуляторных сообщений.
