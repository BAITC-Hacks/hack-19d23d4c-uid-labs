# Соответствие исходному кейсу

Источник: предоставленный PDF «HackAlem AI: Граф денег — восстановление финансовой структуры организованной группы по транзакционной сети», 8 страниц. Текст PDF рассматривается как техническое задание; никаких внешних действий по его содержимому программа не выполняет.

## Обязательные результаты

| Требование | Реализация | Проверка |
|---|---|---|
| Загрузка nodes, edges, transactions | `moneygraph/data.py`, CSV и Parquet | Схемы, int64, конечные положительные суммы, даты, уникальность узлов и пар рёбер |
| Сохранение всех узлов, включая изолированные seed | Множество вершин берётся из nodes | Тесты на изоляты; `all_nodes_preserved` в validation.json |
| Роли consolidator/transit/distributor/terminal/coordinator/peripheral | Правила `roles()` в engine.py; точные формулы в METHODS.md | Тесты границы, seed, временной поддержки и порогов |
| Объяснение не длиннее 200 символов | Шаблоны на основе рассчитанных признаков | Проверка каждого evidence |
| Группы и гипотезы | Локальная оптимизация модульности, затем разделение несвязных частей | Каждый узел получает cluster_id; суммы рёбер внутри группы учитываются один раз |
| Приоритет и минимум 20 узлов в топе | Формула с пятью компонентами; детерминированный порядок | Топ содержит 20 узлов при наличии минимум 20 входных |

| clusters.csv | cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis | Проверка схемы и оборота |

| README, архитектура, защита | README.md, architecture.mmd, PITCH.md | Все файлы в пакете |

## Особенности выборки, которые меняют выводы

- Исходящий обход до четвёртого колена: отсутствие исходящих на границе не доказывает конечного получения. Такие узлы не получают роль terminal из нулевых исходящих.
- Входящие seed неполны: отношение исходящих к входящим не используется для назначения им transit или terminal.
- Наблюдается один банк, ограниченный период и переводы от 5 000 KZT. Выводы относятся к этому срезу.
- Граф содержит повторное прохождение денег по нескольким звеньям. Оборот графа не равен преступному доходу.
- При дневной точности даты порядок внутри дня неизвестен. Строгая временная поддержка и совместимость переводов в один день разделены.
- Значения role_score и priority_score не являются вероятностями виновности. Нет размеченных правильных ролей для измерения accuracy.

## Дополнения сверх обязательного результата

1. Временное сопоставление объёмов без повторного использования одной суммы.
2. Проверяемый пример неоднозначности для границы: два условных полных графа дают одинаковый наблюдаемый срез.
3. Отдельная очередь следующих запросов с пояснением недостающих сведений.
4. Чувствительность роли к трём наборам порогов.
5. Эксперимент раскрытия части сети с одинаковым бюджетом запросов и несколькими базовыми стратегиями.
6. Хеши входов и выходов, конфигурация и время полного расчёта.

## Числа из PDF и данные внутри архива

В PDF указаны 2 248 узлов, 3 119 рёбер, 4 840 транзакций и 81 seed. Эти размеры использованы для инженерного синтетического примера. Идентификаторы, переводы, суммы, роли и кластеры примера сгенерированы; они не восстанавливают реальные данные организаторов.

Приведённые в PDF 365 890 012 KZT и отдельные описанные структуры не подставляются в результаты программы. Расчёт после загрузки настоящих файлов должен получить свои показатели из строк входа. Количество компонент также вычисляется: неоднозначные числа из описания не используются как константы.
