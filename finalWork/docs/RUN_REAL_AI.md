# Работа с предоставленными данными

Проект использует три файла организаторов из пользовательского архива: `data/nodes.parquet`, `data/edges.parquet`, `data/transactions.parquet`. Они скопированы без преобразования. Папка `results/demo/` по-прежнему содержит отдельный синтетический пример; не показывайте его как результаты предоставленного набора.

Наличие исходных транзакций позволяет проверить вычисления и связи. Оно не подтверждает преступление и не даёт эталонной разметки ролей. Счётчик клиентов также не является числом подозреваемых.

## Подготовка Python

Из корня проекта, в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Поддерживаемая версия для закреплённого Parquet-пакета: Python 3.10–3.13. Установщик пакетов требует доступ к сети; после установки графовый анализ работает локально.

## Пересчёт предоставленного набора

```powershell
.\.venv\Scripts\python.exe -m moneygraph run --data data --out results/real --format parquet --stability
```

Результаты: `results/real/dashboard.html`, `report.json`, обязательные CSV и `run_manifest.json`. Манифест содержит контрольные суммы входов и время выполнения. Показатель времени относится к расчёту и экспорту, а не к работе человека и не к языковой модели.

Денежный итог — оборот по операциям: одинаковые средства могут проходить несколько звеньев. Он не означает размер ущерба. Служебные номера `tx-*` обозначают строки конкретной версии файла, а не банковские ID транзакций.

## Проверка воспроизводимости

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts/validate_real_parquet.py
node tests/test_dashboard.cjs results/real/dashboard.html
```

`validate_real_parquet.py` читает все три исходные таблицы, записывает их заново во временные Parquet, сравнивает таблицы и повторно загруженные записи. Результат сохраняется в `results/checks/real-parquet-roundtrip.json`. Исходные файлы не меняются. Команда Node.js проверяет JavaScript и состояние модели DOM; это не проверка расположения элементов в настоящем браузере.

При текущих настройках получены 345 алгоритмических кластеров и 35 слабосвязных компонент, включая 19 изолированных узлов. Это разные понятия; кластеры не означают доказанные организованные группы. Топ содержит 20 кандидатов. Эти числа вычислены из входов, а не заданы в интерфейсе.

Первый полный запуск занял 2,1385 секунды по `run_manifest.json`, включая чтение, анализ, CSV, HTML и хеши. Ранний показатель в `report.json` — 1,0654 секунды; он записан до финальной сериализации. Это один запуск на этой машине, без вызова языковой модели, не гарантия времени для других наборов. Флаг `synthetic=false` означает, что загружены предоставленные файлы вместо встроенного генератора; он не подтверждает банковское происхождение или преступный характер операций.

Отрисовка нового интерактивного интерфейса в настоящем браузере и живой ответ языковой модели проверяются отдельно от перечисленных проверок ядра. Качество ролей на данном наборе не измерено: эталонная разметка не предоставлена.

## Локальное приложение с помощником

После настройки доступного провайдера модели согласно `.env.example` запустите:

```powershell
.\.venv\Scripts\python.exe -m moneygraph serve --data data --out results/real --port 8520
```

Или из PowerShell:

```powershell
.\scripts\start_local.ps1
```

Откройте `http://127.0.0.1:8520`. Статический `results/real/dashboard.html` служит отдельным автономным отчётом; он сам не подключает языковую модель. Если провайдер не настроен или недоступен, приложение должно явно показывать это состояние.

## Границы результата

- Предполагаемые роли и приоритеты нуждаются в проверке сотрудником.
- Время в исходных данных имеет точность до дня: порядок операций внутри дня неизвестен.
- Обрыв наблюдения на четвёртом колене не доказывает, что деньги остались у последнего видимого получателя.
- Расчёт графа и чисел выполняет воспроизводимый код. Наличие отчёта само по себе не означает, что языковая модель подключена.
- Расходы на модель и экономия времени аналитика требуют отдельных измерений. Результаты модульных тестов не измеряют качество расследований.
