# Входные данные

В опубликованном проекте эта папка содержит только описание входного контракта. Файлы `nodes.parquet`, `edges.parquet`, `transactions.parquet` необходимо получить отдельно и поместить сюда локально. Данные исключены из Git через `.gitignore`. Синтетический пример можно сгенерировать командами из корневого README без предоставленного набора.

При локальной проверке автора использовались: 2 248 клиентов, 3 119 агрегированных направленных рёбер, 4 840 транзакций и 81 исходный клиент (seed). Период — 1–31 июля 2026 года. Это статистика предоставленного набора, не число подтверждённых нарушителей. Результаты расчёта находятся в `results/real/`, запись и чтение всех трёх Parquet проверены в `results/checks/real-parquet-roundtrip.json`.

| Таблица | Обязательные поля |
|---|---|
| nodes | gid:int64, depth:int, is_seed:bool |
| edges | src:int64, dst:int64, sum_kzt:number, n_tx:int, depth:int |
| transactions | src:int64, dst:int64, date:ISO date/datetime, sum_kzt:number |

Поддерживаются аналогичные CSV с такими же заголовками. `is_seed` в CSV: true/false/1/0. `gid` нельзя предварительно сохранять через float. Лишние поля не используются.

При открытии CSV в Excel импортируйте gid/src/dst как текст: автоматическое числовое преобразование Excel может потерять цифры длинного int64. В HTML идентификаторы уже передаются строками.

Суммы положительные и конечные. Каждый endpoint должен присутствовать в nodes. Пары edges уникальны; сумма и число транзакций по каждой паре должны совпасть с агрегатом transactions (допуск суммы: max(0.02 KZT, относительный 1e-9)). Идентичные транзакционные строки сохраняются.

Служебные `tx-0000001` назначаются по порядку строк исходной таблицы; это ссылки внутри данной версии выгрузки, не банковские идентификаторы. При замене файла они могут измениться. Версия файла закрепляется SHA-256 в manifest.

`metadata.json` допускается для маркировки инженерных данных: `{"synthetic": true}`. Встроенный синтетический пример хранится отдельно в `results/demo/input/`. При загрузке отдельно предоставленных Parquet без синтетической маркировки загрузчик ставит `synthetic=false`, поскольку это не встроенный генератор. Этот флаг сам по себе не подтверждает банковское происхождение или преступный характер операций.

У дат точность до дня; порядка переводов внутри дня в данных нет. Отсутствие исходящих у границы выгрузки не доказывает конечного получателя. Столбцы не содержат номеров карт и сведений о владельцах: интерфейс использует клиентов/узлы и их `gid`, не выдумывает карты или личности.

Сами данные хакатона имеют ограничение использования из ТЗ. Не публикуйте их в репозитории или сторонних сервисах без разрешения владельца.
